# 素材采集命令

按需读取本文件。下面是从三类来源采集一周工作素材的具体命令。**采集到的是原始素材,不是周报本身——拿到后必须做提炼(合并同类项、抽象成成果、判断状态),见 SKILL.md。**

## 1. Git 提交记录

先确认用户的项目在哪、用没用 git。如果用户没说,可以问,或在常见位置扫一下哪些目录是 git 仓:

```bash
# 在某个根目录下找出所有 git 仓
for d in <搜索根目录>/*/; do
  [ -d "$d/.git" ] && echo "GIT: $d"
done
```

确认仓库后,取本周提交。把 `<repo>` 换成项目路径,`<author>` 换成用户的 git 用户名(`git -C <repo> config user.name` 可查);只总结用户自己的工作时才加 `--author`,否则去掉它取全部提交:

```bash
# 最近 7 天的提交(标题 + 日期)
git -C <repo> log --since="7 days ago" [--author="<author>"] \
  --pretty=format:"%h | %ad | %s" --date=short

# 带改动规模(看哪些 commit 是大动作)
git -C <repo> log --since="7 days ago" \
  --shortstat --pretty=format:"%h %s" --date=short

# 看具体改了哪些文件(判断成果归属哪个模块)
git -C <repo> log --since="7 days ago" \
  --name-only --pretty=format:"%h %s" --date=short
```

**重要**:git log 经常很稀薄(刚建仓、只有 "Initial commit",或项目根本没用 git)。git 空 ≠ 这周没干活。这时把权重转到文件改动和用户口述。

## 2. 项目文件改动时间线

当 git 稀薄时,这是还原工作脉络的主力。列出最近 7 天被修改的文件,按时间排序:

```bash
# 某个项目目录下,最近 7 天改动的文件(排除常见噪音目录)
find <项目目录> -type f -mtime -7 \
  -not -path "*/.git/*" -not -path "*/node_modules/*" \
  -not -path "*/__pycache__/*" -not -path "*/build/*" \
  -printf "%TY-%Tm-%Td %TH:%TM | %p\n" 2>/dev/null | sort
```

跨多个项目时,把 `<项目目录>` 换成它们的公共父目录,但结果会很多——建议先和用户确认聚焦哪几个项目。

读文件改动时,关注:**新建的文件**(往往代表新产出)、**反复修改的文件**(代表本周主攻点)、**产物类文件**(.pdf / .docx / 生成的图、模型,代表可交付成果)。

## 3. 用户口述 / 粘贴

最高权重。用户说的主线,就是周报的主线。git 和文件只用来补全细节、佐证、补充用户可能忘了提的事。

如果用户既没口述、git 又稀薄、文件也没什么改动——别硬编。如实说"没找到这周的工作痕迹",请用户讲讲做了什么。

## 提炼的要点

采集完三类素材后:

- **合并**:同一件事的多个 commit / 多个文件 → 一条成果。
- **抽象**:"改了某脚本" → "完成某功能/某文档"。问"这件事的产出和价值是什么",而不是"动了哪个文件"。
- **判断状态**:已完成 / 进行中 / 受阻。受阻的最有汇报价值。
- **量化**:有真实数字(文件数、测试通过、性能提升)就带上,但不许编。
