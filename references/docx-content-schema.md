# 周报 .docx 内容 JSON 结构

`scripts/build_docx.py` 接收一个 JSON 文件,产出排版好的 Word 周报。先把整理好的内容写成下面这个结构的 JSON,再调脚本。

## 字段说明

```json
{
  "name": "张三",
  "period_start": "2026-05-28",
  "period_end": "2026-06-03",
  "achievements": [
    {
      "title": "完成订单服务的支付回调重构",
      "detail": "把回调逻辑从单体里拆出独立模块,补齐幂等校验,线上重复回调导致的重复发货问题已消除。",
      "status": "done",
      "project": "订单系统"
    }
  ],
  "in_progress": [
    {
      "title": "新版报表导出性能优化",
      "detail": "大数据量导出从同步改为异步任务,已完成后端,前端进度提示还在联调。",
      "eta": "下周三",
      "project": "数据平台"
    }
  ],
  "blockers": [
    {
      "title": "测试环境数据库频繁超时",
      "detail": "近一周测试库连接超时多次,影响联调效率,疑似资源配额不足。",
      "need": "希望运维协助排查测试库资源配额。"
    }
  ],
  "next_week": [
    "完成报表导出优化并上线",
    "推进订单服务的灰度发布"
  ]
}
```

## 字段含义

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 汇报人姓名,用于标题。缺省则标题不带姓名。 |
| `period_start` / `period_end` | 是 | 周报覆盖的起止日期,`YYYY-MM-DD`。 |
| `achievements` | 是 | 本周核心成果,数组。每条含 `title`(一句话成果)、`detail`(可选补充)、`status`、`project`(可选,多项目时用于分组)。 |
| `in_progress` | 否 | 进行中事项。`eta` 是预计完成时间(可选)。 |
| `blockers` | 否 | 问题与需要的支持。`need` 写清希望上级提供什么(可选)。空数组则文档里写"本周无"。 |
| `next_week` | 是 | 下周计划,字符串数组,每条一个目标。 |

`status` 取值:`done`(已完成)、`doing`(进行中)、`blocked`(受阻)。脚本会渲染成对应颜色的徽章(绿/蓝/红)。

## 排版

脚本已内置一套现代中文公文排版,无需额外配置:标题用微软雅黑、正文用等线、1.4 倍行距;深蓝标题 + 中蓝强调色;小节标题带左侧色条与分隔线;状态徽章带底色;顶部主题色横幅、标题下"本周 N 项成果"速览行、页脚页码。样式逻辑集中在 `scripts/docx_style.py`,要改主题色或字体改那里即可,不必动 `build_docx.py`。

## 多项目分组

当 `achievements` 里的条目带了不同的 `project` 值,脚本会自动按项目分小标题组织"本周核心成果",让跨项目的周报读起来不混乱。如果都不带 `project` 或只有一个,就平铺成一个列表。

## 注意

- 这个 JSON 是**提炼后**的内容,不是原始 git log。把素材抽象成成果后再填进来。
- 不许编造。`detail` 和数字必须有素材支撑,拿不准的就别写进 `detail`,或先问用户。
