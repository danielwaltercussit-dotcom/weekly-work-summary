# weekly-work-summary

一个 Claude / Claude Code **Skill**:把零散的一周工作,整理成一份**给上级看的、专业、可直接上交的周报**,默认输出排版精致的 Word(.docx)。

## 它解决什么问题

周报最常见也最致命的失败,是退化成操作流水账——"改了 X 文件、跑了 Y 脚本、提交了 Z 次"。上级不关心你敲了哪些键,他关心**事情推进到哪了、产出了什么、有没有风险需要他介入**。这个 skill 的核心就是把底层操作(commit、文件改动、调试过程)**向上抽象成成果与影响**,并坚守一条硬规则:**绝不编造进度**——素材不足时宁可问用户,也不凭空拔高。

## 特性

- **三类素材自动采集**:git 提交记录、项目文件改动时间线、用户口述/粘贴,交叉印证。
- **成果导向**:结论先行,把多个 commit / 文件改动合并抽象成一条条"做成了什么 + 价值"。
- **面向上级的固定结构**:本周核心成果 → 进行中事项 → 问题与需要的支持 → 下周计划。
- **精致的中文 Word 排版**:微软雅黑标题 + 等线正文、1.4 倍行距、深蓝主题色、彩色状态徽章(绿=已完成 / 蓝=进行中 / 红=受阻)、小节色条、页脚页码。
- **绝不编造**:这是写进 skill 的第一硬规则,因为周报会送到领导面前。

## 安装

把整个 `weekly-work-summary/` 文件夹放进你的 skills 目录即可:

- **Claude Code**:放到 `~/.claude/skills/`(全局)或项目的 `.claude/skills/` 下。
- **.skill 包**:若拿到的是 `weekly-work-summary.skill` 文件,按你的客户端的"导入 skill"方式安装。

## 依赖

只有一个 Python 包,用于生成 Word:

```bash
pip install python-docx
```

## 用法

安装后,直接像平时说话一样触发,例如:

- "帮我总结一下这周的工作,写成周报发给领导"
- "周五了,看下我那个项目这周的提交,整一份本周工作汇报的 word"
- "把我这周干的活整理成周报"

skill 会采集素材、提炼成果、和你确认缺口,然后生成 .docx 并告诉你文件路径;遇到受阻、需要上级决策的事项,还会额外口头提醒你。

## 目录结构

```
weekly-work-summary/
├── SKILL.md                      # 触发规则 + 核心理念 + 工作流
├── references/
│   ├── data-collection.md        # git/文件/口述 三类素材采集命令
│   └── docx-content-schema.md    # 周报内容 JSON 结构与示例
├── scripts/
│   ├── build_docx.py             # 周报内容 JSON → Word
│   └── docx_style.py             # 字体/配色/徽章样式(改主题色看这里)
└── evals/evals.json              # 测试用例(可选,用于评估 skill 质量)
```

## 自定义

- **换主题色 / 字体**:改 `scripts/docx_style.py` 顶部的 `PRIMARY`、`ACCENT`、`FONT_*` 常量即可,不必动 `build_docx.py`。
- **改周报结构**:在 `SKILL.md` 的"周报结构"一节调整。
